AI エージェントが、ほかのコーディングエージェントに独立した意見を求め、答えを相談相手ごとに受け取るためのプラグインです。

相談相手は Codex・Claude Code・Antigravity・OpenCode です。作業中のエージェント（主担当）は、調査に行き詰まったときや、
甲乙つけがたい選択に当たったときに相談します。あなたから「Codex に聞いて」と頼むこともできます。

答えは相談相手ごとに返ります。主担当は、指摘の根拠や意見が割れた理由を自分で確かめ、その結果をもとに作業を続けます。
巻き戻しにくい変更のような重要な判断では、承認を求める前に相談し、あなたが決めるべきことだけを訊きます。

たとえばキャッシュの相談では、会員ごとの価格がほかの利用者に漏れる問題を指摘できます。主担当は価格の前提を
確かめ、何をキャッシュするかを決め、未確認の点を記録します。[使い方の例](docs/how-it-works.ja.md#使い方の例)で、
相手別の提案から判断までを追えます。

## インストール

### 必要なもの

- Node.js 22 以降。OpenCode 2.x の認証回復の一部には `node:sqlite` が必要で、使えるかどうかは `status` に表示します。
  使えない環境でも通常のログインは動作する場合があります。[必要条件の詳細](docs/install.ja.md#必要なもの)を参照してください。
- インストールしてログインした CLI（4 つのうち少なくとも 1 つ）。1 つで足り、Claude Code だけでも、新しい
  Claude Code のセッションに相談できます。

相談したい CLI は、[導入・ログイン方法へのリンク](docs/install.ja.md#必要なもの)から準備できます。

### 入れる

次のコマンドは severally を入れて既存の CLI に登録するもので、CLI 自体の導入やログインは行いません。
macOS、Linux、Windows（PowerShell またはコマンドプロンプト）のどれでも、次の 1 行で入れられます。

```bash
npx -y -p https://github.com/coz-a/severally/releases/download/v2.9.1/severally-mcp-2.9.1.tgz severally-install
```

インストーラは、`PATH` で見つかった CLI のそれぞれに severally を登録します。末尾に `--dry-run` を付けると、何も
変えずに変更内容だけを表示します。

終わったら、クライアントを再起動してください。動いているセッションは、新しい登録を読み直しません。相談を始めずに
設定を確かめるには、次を実行します。

```bash
npx -y -p https://github.com/coz-a/severally/releases/download/v2.9.1/severally-mcp-2.9.1.tgz severally-mcp status
```

設定ファイル・この機械から使える相談相手・入っている写しの版・どのクライアントに登録されているか・各 CLI に
ログインしているかを表示します。ログインの確認は CLI 自身の状態確認コマンドを読むだけで、プロンプトは送りません。
使用枠を使い切っていないかは確かめません。それは最初の相談で分かります。

Codex と Claude Code がある機械での出力の一部を示します。

```text
config: ok

consultants:
  codex: codex, gpt-6.1-sol  available
  claude-code: claude-code, claude-opus-5-5  available

clients:
  Claude Code  registered (listed by the client)
  Codex        registered (listed by the client)

login (out of quota is not checked; the first consultation shows it):
  codex        logged in
  claude-code  logged in
```

通常は無設定で使えます。最初の相談のしかたは[頼み方](#頼み方)にあります。

マーケットプレイスやクローンからの導入、グローバルインストールができないときの動作は
[インストールの詳細](docs/install.ja.md)に、`--dry-run`、`--manual`、`--force` などの使い方は
[インストールのオプション](docs/install.ja.md#コマンドライン)にあります。

インストーラとサーバは、CI で Linux・macOS・Windows のテストをしています。Claude Code と Codex のマーケットプレイスからの
導入と、実際の CLI での動作を試したのは Linux だけです。Windows で相談を取り消すと、相談相手の CLI が動いている間なら
プロセスの木ごと止まります。CLI が先に終わっていた場合は、CLI が起動したプロセスが残ることがあります。
その場合に何が残るかは、テストで観察しているだけで、保証していません。

### 更新

このリリースは GitHub Release のアーカイブで配布します。2.9.1 への更新には次のコマンドを使います。

```bash
npx -y -p https://github.com/coz-a/severally/releases/download/v2.9.1/severally-mcp-2.9.1.tgz severally-install
```

今後の更新には、[最新の GitHub Release](https://github.com/coz-a/severally/releases/latest) に添付したアーカイブを使ってください。
`severally-mcp@latest` は npm の最新版を指します。2.9.1 は npm には公開していません。
Claude Code にマーケットプレイス版の severally が入っていれば、同じ 1 行でその写しも更新されます（詳しくは
[docs/install.ja.md](docs/install.ja.md#更新)）。終わったら、クライアントを再起動してください。版ごとの変更点は
[リリース](https://github.com/coz-a/severally/releases)にあります。

### アンインストール

マーケットプレイスから入れた場合は、Claude Code で `/plugin marketplace remove severally` を実行します。プラグインも
一緒に取り除かれます。インストーラで入れた場合のコマンドは、OS とインストール方式ごとに
[docs/install.ja.md](docs/install.ja.md#アンインストール) にあります。どの場合も、履歴とバックアップは `~/.severally/` に
残るので、要らなければ消してください。

## 使い方

### 頼み方

再起動したエージェントとのチャットに、次のように頼んでください。

```text
Codexに聞いて。読み取り専用の公開APIに毎分100件のリクエストがあります。
更新の反映は60秒遅れてもよい場合、30秒間のキャッシュは妥当ですか？
```

Codex がなければ、`status` で `available` と出た相談相手を使います。報告は次のようになります。回答モデルと、
確かめたこと・未検証のことは相談によって変わります。

```text
Codex（gpt-6.1-sol）は、30秒のキャッシュを候補に挙げました。30秒は許容する60秒以内です。
ほかのキャッシュを重ねた場合の遅延は未検証なので、その合計が60秒以内か確かめてから
採用してください。
```

続けて「更新を5秒以内に反映する必要がある場合も、同じ相手に聞いて」と頼めます。

ふだんの言葉で頼み、質問の中に前提を書きます。コードの相談では、対象のファイルか変更を伝えます。

```text
> この移行計画が安全か Codex に聞いて
> このキャッシュの設計にセカンドオピニオンをもらって
> マージする前にみんなに聞いて
```

- 相談相手を名指しすると（「Codex に聞いて」「Claude Opus に聞いて」）、その相手だけに聞きます。CLI の名前でも、
  モデルの名前でも呼べます。
- 名指しせずにセカンドオピニオンを頼むか、全員に聞くよう頼むと、すべての相談相手に同じブリーフを送ります。
  自分の CLI の新しいセッションも含みます。使用量は、相談相手 1 人につき 1 回分です。
- 頼まなくても、エージェントは自分から相談します。調査が行き詰まったとき、甲乙つけがたい選択に当たったとき、
  巻き戻しにくい変更の承認を求める前です。

あなたに返ってくるのは、相談相手の答えそのものではなく、主担当の報告です。確かめたことと結果、勧めること、
まだ確かめていないことが並びます。報告の例は[使い方の例](docs/how-it-works.ja.md#使い方の例)にあります。

相談が向いているのは、重要な設計判断、巻き戻しにくい選択、同じ不具合で 2 回以上失敗したときです。相談 1 回に
数分から 10 分ほどと実際の使用量がかかるので、小さな修正には向きません。

### 答え・検証・失敗

答えを待つ間、エージェントは答えに左右されない作業を進められます。所要時間はふつう 1〜10 分で、CLI・モデル・
負荷によって変わります。各回答には結論、根拠つきの指摘、不明点、確かめ方を求めます。
`usage_limit` や `timeout` などで失敗した場合は、助言を得られなかったという意味です。

主担当は判断を変え得る指摘を確かめ、検証の根拠と採否を分けて記録します。報告には、相手の実際のモデル、判断を
左右した指摘と ID、確認結果、推奨、未検証の点を含めます。異なる結論は分けて残します。1 人が失敗しても、成功した
相手の答えは使えます。必要なら、失敗した相談だけを再実行できます。

### 追加質問と履歴

「昨日のキャッシュ相談の続きを聞いて」「更新したコードで、あの指摘を確かめ直して」と頼めます。エージェントが
保存済みの相談を探すので、ID の転記は要りません。候補が複数あれば、どれを指すか確認します。同じ相手との相談は、
既定では最初の質問を含めて 5 回までです。ファイルは今の内容で送り直し、変更と削除を注記します。

相談と検証の記録は `~/.severally/history/` に残ります。別のセッションから追記でき、Markdown にも書き出せます。
書き出しの先頭には検証済みの指摘、判断への影響、未検証件数が並び、そのあとに回答全文が続きます。
`confirmed` は確認で成り立ったという意味で、助言を採用したという意味ではありません。
[モードと追加質問の詳細](docs/how-it-works.ja.md#相談の進み方)と[記録](docs/how-it-works.ja.md#記録)を参照してください。

## 設定

**既定のままなら設定は要りません**。サーバは起動時に `PATH` にある CLI を探し、見つかった CLI をそれぞれ、既定の
モデルで動く相談相手にします。CLI を止める、ほかのモデルの相談相手を足す、といったときは
`~/.severally/config.jsonc` または `config.json` を置きます。両方あるときは `config.jsonc` が優先されます。クローンから入れた場合は、`npm run init-config` でひな形を作れます。キーは
すべて [CONFIG.md](CONFIG.md)（英語）にあり、[config.example.json](config.example.json) は書き換えて使う例です（パス・モデル・メモは架空のものです）。
普段の作業と相談でモデルを分けたい場合は、[複数モデルの設定例](docs/how-it-works.ja.md#おすすめの構成)を参照してください。
設定を変えたら、クライアントを再起動してください。

API キーで呼び出すモデル（OpenRouter や、OpenAI 互換のほかの API）やローカルのモデルに相談するには、OpenCode を入れて、
そのモデルを相談相手に足します。書き方は
[OpenCode の設定手順](CONFIG.md#api-keys-and-other-model-families-through-opencode)（英語）にあります。

## 相談相手が読めるものとできること

相談では、ブリーフをその CLI のモデルに送ります。あなたが自分でその CLI を使うときと同じです。
親セッションの会話履歴は自動で引き継ぎません。ただし、主担当がブリーフに含めた内容や、相談相手に読み取りが許された
ファイルの内容は、そのモデルに送られます。読み取り専用という設定は、読める範囲の隔離ではありません。
どの相談相手も、次のことはできません。

- ファイルを書く
- MCP を使う
- ほかのエージェントを起動する、ほかの誰かに相談する
- Web 検索と閲覧のほかにネットワークを使う

| 相談相手 | ファイルの読み取り | 秘密のパス | シェル | 書き込み | Web 検索・閲覧 |
|---|---|---|---|---|---|
| Codex | できる | パスで拒否（権限プロファイル）。`.env` のようなファイル名では拒否しない | ある。サンドボックスの中（コマンドは動くが、書き込みとネットワークはできない） | できない | できる（`network: "off"` のときを除く） |
| Claude Code | できる（`Read` / `Glob` / `Grep`） | 拒否（権限の規則） | なし | できない | できる（`network: "off"` のときを除く） |
| Antigravity | できる（`view_file`・`read_file`） | 拒否（ツールのフック） | なし | できない | できる（`network: "off"` のときを除く） |
| OpenCode | できる（`read`） | 権限の規則と読取り前の実パス検査で拒否。制約は表の下に記載 | なし（Code Mode の `execute` は拒否） | できない | できる（`network: "off"` のときを除く） |

どの相談相手も、渡したファイルの写しだけが入った専用の作業ディレクトリで始まり、サーバはあなたのリポジトリの
場所を伝えません。それでも、あなたのユーザーアカウントで読めるファイルは、表で「拒否」とした秘密のパスを除いて
読めます。例外は、ファイルを渡した相談での Claude Code です。そのときは、渡したファイルの写ししか読めません。
Codex はファイルの名前では拒否しないので、あなたのリポジトリにある `.env` は Codex から読めます。
既定の `~/.codex` を含む資格情報ディレクトリは、Codex の実行ファイルが外にあれば全体を拒否します。
保護対象の中に実行ファイルがある場合は、実行ファイルを含む項目を読取り可能なまま残し、ほかの項目を起動時点で
列挙して拒否します。その後に増えた項目は対象外です。Linux では、個別に拒否したファイルが実行中に rename で
置換されると読めることがあります。既知の環境変数で指定した絶対パスは保護しますが、任意の資格情報の場所は自動検出しません。
OpenCode は読取りのたびに指定パスと実パスを調べ、シンボリックリンクの別名経由も拒否します。ただし、フックの検査から
CLI の読取りまでの間に実パス側が差し替わる場合は保証しません。これらの変更は Linux の Codex 0.164.0 と
OpenCode 2.0.24 で確認しました。macOS・Windows と、ほかの CLI バージョンでの強制結果は未検証です。

**ディスクを読めて Web も閲覧できる相談相手は、読んだ内容を URL に載せて外に持ち出せます**。開いたページに、
そうするよう書かれていた場合などです。それを防ぎたいときは、エージェントが `network: "off"` を渡します。その回の
どの相談相手も、Web の検索と閲覧ができなくなります。すべての相談でそうするには、
[設定ファイル](CONFIG.md#server-wide-keys)に `"server": { "network": "off" }` と書きます。依頼の側からは戻せません。それでも、ブリーフと相談相手が読んだ内容は、その CLI の
モデルに送られます。

CLI ごとにどう守らせているかは [docs/how-it-works.ja.md](docs/how-it-works.ja.md#相談相手を読み取りだけにとどめる仕組み) にあります。

## API

サーバの MCP ツールは 6 つです。そのうち外部への相談を開始するのは `consult_start` だけで、ブリーフと公開したファイルを
各相談相手のモデルに送ります。起動した相談相手は、許可された範囲でファイルを読み、Web を閲覧でき、その内容もマシンの外に
送られます。ほかの 5 ツールは、手元の相談状態や記録を操作します。引数はすべて、エージェントが読むツールの説明に書いてあります。

| ツール | すること |
|---|---|
| `consult_start` | 1 人（`target`）または複数（`targets`）に相談する。`retry_of` は失敗したジョブだけを再実行する |
| `consult_get` | 相談を待ち、状態か答えを返す。`ids` を付けると、答えのうちその指摘だけを返す |
| `consult_cancel` | 相談、または全員に聞いた相談をまとめて止め、相談相手のプロセスも止める。別のセッションが始めた相談も止められる |
| `consult_record` | 答えの指摘ごとの主担当の判定と、答えから新しく分かったことを書く |
| `consult_list` | 相手・質問・相談の ID で履歴を探し、継続先の ID とセッションの使用量を返す |
| `consult_export` | 相談を、追加の質問と判定を含めて Markdown で返す |

引数とファイル公開の詳細は[仕組みの文書](docs/how-it-works.ja.md#apiの引数)にあります。

## 貢献

質問と不具合の報告は [Issues](https://github.com/coz-a/severally/issues) へどうぞ。プルリクエストも歓迎します。
大きな変更は、先に Issue で相談してください。参加する方は、[行動規範](CODE_OF_CONDUCT.md)に従ってください。

- `npm install` のあと `npm test` を実行します。テストは本物の代わりに用意した CLI を相手にオフラインで動き、
  実際の API は呼びません。
- CI では `npm run lint`・`npm run typecheck`・`npm run format:check` も確かめています。プルリクエストを出す前に
  実行してください。
- ソースか Skill のテンプレートを変えたら、`npm run build` を実行してください。ビルド済みのサーバ
  （`plugins/severally/dist/`）と生成した Skill はコミットしてあり、古いままだと CI が失敗します。
- `npm run live-check` と `npm run doctor` は、入っている CLI を相手に本物の相談を実行するので、実際の使用量がかかります。
  `doctor` は各 CLI の版も表示します。リリースの前に、手元の CLI を相手に両方を実行し、CLI の版・確認日・OS を
  リリースノートに残してください。
